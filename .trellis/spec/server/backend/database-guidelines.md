# Database Guidelines

## ORM: Drizzle ORM + SQLite

The server uses **Drizzle ORM** with **better-sqlite3** (WAL mode, foreign keys enabled).

### Defining Tables

Define tables in `server/src/db/schema/<table>.ts` using `sqliteTable()`:

```typescript
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core'

export const courses = sqliteTable('courses', {
  id: text('id').primaryKey(),               // UUID string, generated by code
  title: text('title').notNull(),
  duration: integer('duration').notNull(),
  category: text('category').notNull(),       // enum stored as text
  instructor_id: text('instructor_id').references(() => instructors.id, { onDelete: 'set null' }),
  created_at: text('created_at').notNull().default(new Date().toISOString()),
})
```

Reference: `server/src/db/schema/courses.ts`, `server/src/db/schema/users.ts`

### Conventions

- **Primary keys**: Text UUIDs (`crypto.randomUUID()`), not auto-increment integers.
- **Timestamps**: `text` columns storing ISO 8601 strings, not `integer` epoch seconds.
- **Booleans**: `integer` columns with `0`/`1` values (SQLite has no native boolean).
- **Enums**: Stored as `text` with application-level validation (no SQLite CHECK constraints).
- **JSON in text**: The `courses.tags` column stores `JSON.stringify(array)` in a `text` field. Always call `parseTags()` on read.
- **Foreign keys**: Use `.references()` with explicit `onDelete` behavior (`'cascade'` or `'set null'`).
- **Re-exports**: `server/src/db/schema/index.ts` re-exports all table definitions for convenient imports.

### Relationships

```
instructors  1──N  courses  N──1  series
                         N──N  series (via series_courses join table)
progress:  (user_id, course_id) composite PK
```

- `courses.instructor_id` → `instructors.id` (SET NULL on delete)
- `courses.series_id` → `series.id` (CASCADE on delete)
- `series_courses` — many-to-many join with composite PK `(series_id, course_id)`

### Query Patterns

Inject the Drizzle instance via the `DRIZZLE` token (provided by `DbModule`):

```typescript
import { Inject, Injectable } from '@nestjs/common'
import { DRIZZLE } from '@/modules/db/db.module'
import { courses } from '@/db/schema'
import { eq } from 'drizzle-orm'

@Injectable()
export class CoursesService {
  constructor(@Inject(DRIZZLE) private db: DrizzleDB) {}

  async findById(id: string) {
    return this.db.select().from(courses).where(eq(courses.id, id)).get()
  }
}
```

Common query patterns in this codebase:

- `.get()` — single row (returns `undefined` if not found)
- `.all()` — multiple rows
- `.where(eq(...))` — filtering
- `onConflictDoNothing()` — idempotent inserts in seeds

### Migrations

The project uses **Drizzle Kit** for schema management:

```bash
npx drizzle-kit generate   # generate migration from schema changes
npx drizzle-kit migrate    # apply migrations
```

Configuration: `server/drizzle.config.ts` (dialect: sqlite, schema: `./src/db/schema/*.ts`).

The seed file (`server/src/seed.ts`) also creates tables with raw `CREATE TABLE IF NOT EXISTS` SQL for bootstrap scenarios.

### Anti-Patterns

- Using `ilike` with SQLite — SQLite's `LIKE` is already case-insensitive for ASCII. `ilike` is semantically misleading and may break with non-ASCII characters. Reference: `courses.service.ts` line 24.
- Forgetting `parseTags()` when reading the `tags` column — always returns a raw JSON string otherwise.
- Using synchronous `.get()`/`.all()` inside `async` methods without noting the sync nature — better-sqlite3 calls are synchronous.
